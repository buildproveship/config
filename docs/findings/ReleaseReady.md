# ReleaseReady — findings (2026-11-18, commit 13ce4b2)

Summary: Large (≈289k lines, 1,454 tracked files) but disciplined repo: strict TypeScript, pinned SHAs, AJV-validated boundaries, almost no suppressions (2 `@ts-*`, 5 `any`, 0 skipped tests). Health is held back by tooling and structure rather than code hygiene.
Top 3 risks: (1) no automatic CI on any PR or push, and ESLint only runs in the external manual scanner, so `npm run check` has no code lint; (2) parallel v1/v2 API stacks and many "legacy" data readers kept with no confirmed consumer, although nothing is in production; (3) a local copy of the v8 design components (≈1,970 lines) that duplicates `@releaseready/ui-web/v8`.
Tool results: format:check / typecheck / build / contracts:check / source:check / lint (OpenAPI only) passed on 13ce4b2; `npm test` 3,456/3,490 pass. The same 34 fail on unchanged main on this machine: 19 pass once the agent shell's `ANTHROPIC_BASE_URL`/`AWS_PROFILE` are unset (the Dev isolation guard rejects them), and 15 need filesystem immutability (frozen/sealed artifact tests) that the external volume does not give. ## Notes

- The ReleaseReady worktrees created for this review had `node_modules` symlinked to the owner's checkout (`/Volumes/NINJAV/repos/ReleaseReady/node_modules`, branch fix288 dependencies). `build:adapter` compiles packages inside `node_modules`, so a check run there writes into the owner's install. I removed only the link and ran `npm ci` locally. Siblings should check for this before they run builds.
- The earlier in-repo audit [RRDSCRUM-75](https://noisegatemusicstudios.atlassian.net/browse/RRDSCRUM-75) (docs/audits/sdk-and-node-library-audit.md, 38 items) overlaps RR-01, RR-07, RR-10, RR-11 and RR-12. Its items 11 and 36 are now resolved by PR #322, but the audit doc itself has not been updated.
- Repo rules require an RRDSCRUM ticket per branch/PR. These PRs have no ticket; the owner's merge authorisation came through the review brief.
