# releaseready-product-tests — findings (2026-11-18, commit 99241bdf9b67e8fd5c28ca9336a8a49c65ce7098)

Summary: Small, strictly typed TypeScript repo (11.7k lines of TS, strict, no suppressions, 0 audit advisories), but it is mostly a **second copy** of `ReleaseReady/apps/browser-tests`, kept in step by hand-made "mirror" PRs, with no CI and no linter.
Top 3 risks: (1) SSOT: 78 support/feature files are byte-identical copies of the central tree and 6 have already drifted; seeded accounts are defined three times (constants, recipe JSON, TDM plan). (2) Nothing runs the checks automatically, so `main` had 3 failing unit tests (macOS temp-path fixtures) that nobody saw. (3) Hand-rolled code where the framework or a library already exists: Gherkin case-ID derivation ported from ReleaseReady, WCAG contrast maths copied in three repos, hand-written validation and Cucumber-JSON parsing next to UPF's zod schemas and an unused-for-this `ajv`.
Tool results: `npm run typecheck` 0 errors. `npm run test:unit` on main: 159 tests, **156 pass, 3 fail** (all macOS `/var` → `/private/var` fixture paths). After the fix PRs: **168/168** pass, typecheck 0 errors. `verify:case-identity` and `verify:manifest` (90 entries) pass. `npm audit --omit=dev` 0, `npm audit` 0. `npm outdated` 3 (majors: typescript 5.9→7.0, @cucumber/gherkin 42→43, @types/node 22→26 intentional, matches engines). Suppressions: 0 `eslint-disable`, 0 `@ts-ignore/expect-error`, **6 `any`** (RPT-21), 0 `.skip/.only`. **No linter configured.** **knip and jscpd not run**: the auto-mode classifier blocked `npx -y` package downloads (same as frontend-ui). Substitutes: a git-grep unused-export scan (3 dead runtime exports, ~25 needlessly exported types) and a file-level comparison with ReleaseReady (78 identical, 6 drifted of 84 shared files).
