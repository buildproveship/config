# universal-appium2-framework — findings (2026-11-18, commit 90ad99cc02be09850446d05dc7ace8395880dce8)

Summary: A small, healthy WDIO 10 + Appium 3 + Cucumber template (about 2,750 tracked lines). The runner config uses the official WDIO Appium service, Cucumber framework and reporters, with no custom waits, gestures, retries or reporters. Most of the code is outside the runner: an offline preflight (RRDMOBILE-9) and a scenario-preparation module (RRDMOBILE-1).
Top 3 risks: (1) the preflight's dependency and Node checks re-implement what `npm ls`, `engine-strict` and `appium driver doctor` already do, and it has its own argv parser; (2) the scenario-preparation module has no consumer and depends on undeclared transitive packages; (3) ESLint is not type-aware even though `projectService` is on, and nothing runs the checks automatically (CI is manual by owner decision).
After fixes (main c2b9a9a): `npm ci --ignore-scripts && npm run check:offline` passes with type-aware ESLint (0 problems), Prettier over the whole repo (0 files) and 35/35 node:test; every test file has a classification header; 0 unlisted or unused dependencies found by the import scan.
Tool results: `npm run check:offline` passes (typecheck 0 errors, ESLint 0, Prettier allowlist 0; node:test 9 + 14 + 10 + 2 = **35 pass, 0 fail, 0 skipped**). `prettier --check .` = **3 files unformatted** outside the allowlist. ESLint `recommendedTypeChecked` = **15 errors** (2 unsafe `any` in src, 13 in tests). Suppressions: 0 `eslint-disable`, 0 `@ts-ignore`/`@ts-expect-error`, 0 `any`, 0 `.only`/`.skip`; 1 non-null assertion (tests/preflight/guard.ts:60). `npm audit --omit=dev` 0; `npm audit` **17 high**, all dev-only picomatch ReDoS (GHSA-fc5q-39xc-vjpf) via @wdio/cli, expect-webdriverio and typescript-eslint, with no patched release (4.0.7 is the latest). `npm outdated` 9 (majors: typescript 5.9→7, @types/node 22→26, held by `engines`; minors: appium 3.8→3.9.1, eslint, prettier, typescript-eslint, globals, dotenv, @wdio/appium-service). **knip and jscpd not run**: the auto-mode classifier blocks `npx -y` downloads (same as the other sessions). Substitutes: an import scan of every tracked TS file against package.json (5 unlisted packages, 1 unused) and a manual read of every file (the repo is small enough). Test classification headers: **1 of 8** test files had one. Consumers checked: no repo imports this code; ReleaseReady only holds a revision-pinned inventory snapshot (`scripts/repository-inventory/generated/releaseready--universal-appium2-framework.1.json`).
